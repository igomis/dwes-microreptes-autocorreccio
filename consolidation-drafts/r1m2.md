# R1M2. Consolidació: Entorn executable, landing inicial i tancament de R1

Esta fitxa es consulta després del treball d’aula. Servix per entendre errors i continuar aprenent; no és una nova entrega ni una recuperació individual del microrepte. La recuperació, si cal, correspon al repte complet.

## 1. Què cal entendre

Arrancar contenidors no prova que el producte siga accessible. Cal distingir servidor web, execució PHP, BBDD i phpMyAdmin, i connectar-los amb una landing que explique el producte.

## 2. Exemple mínim explicat

En una base de préstec de material, la landing «Material disponible» és servida pel backend. El port que obris al navegador és el publicat en el host; dins de la xarxa Docker, la connexió a BBDD usa el nom del servei definit en la configuració, no el `localhost` del navegador.

### Fitxers de l’exemple

Crea una carpeta de pràctica amb esta estructura. El nom és `docker-compose.yml`, amb guionet; Compose el detecta automàticament.

```text
practica-r1m2/
├── docker-compose.yml
└── public/
    └── index.php
```

Este exemple és per a l’entorn local d’aula. Les claus que apareixen són valors demo coneguts i els ports només s’obrin en `127.0.0.1`.

### `docker-compose.yml`

```yaml
services:
  web:
    image: php:8.3-apache
    ports:
      - "127.0.0.1:8080:80"
    volumes:
      - ./public:/var/www/html:ro

  db:
    image: mariadb:11.4
    environment:
      MARIADB_ROOT_PASSWORD: root_demo_local
      MARIADB_DATABASE: material_viu
      MARIADB_USER: alumne
      MARIADB_PASSWORD: alumne_demo_local
    volumes:
      - dades_db:/var/lib/mysql
    healthcheck:
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      interval: 5s
      timeout: 5s
      retries: 20
      start_period: 30s

  phpmyadmin:
    image: phpmyadmin:5.2-apache
    ports:
      - "127.0.0.1:8081:80"
    environment:
      PMA_HOST: db
      PMA_PORT: 3306
    depends_on:
      db:
        condition: service_healthy

volumes:
  dades_db:
```

`web` inclou Apache i PHP; no cal un servei addicional per a cada peça. El muntatge posa `public/` en l’arrel web, en mode lectura per al contenidor: pots editar els fitxers des del teu ordinador. `db` conserva les dades en un volum. phpMyAdmin es connecta a `db:3306` per la xarxa interna de Compose i espera que la BBDD estiga preparada. No cal publicar el port de MariaDB al teu ordinador.

La landing és independent de la BBDD: pot arrancar sense esperar-la. Esta imatge de PHP servix la pàgina; l’exemple no configura encara una connexió PDO des del codi ni una funcionalitat de persistència del producte.

### `public/index.php`

```php
<?php
$producte = 'Material Viu';
$recursos = ['Projector', 'Micròfon', 'Càmera'];
?>
<!doctype html>
<html lang="ca">
<head>
    <meta charset="utf-8">
    <title><?= htmlspecialchars($producte, ENT_QUOTES, 'UTF-8') ?></title>
</head>
<body>
    <h1><?= htmlspecialchars($producte, ENT_QUOTES, 'UTF-8') ?></h1>
    <p>Un punt de trobada per consultar i compartir material del centre.</p>
    <h2>Recursos del projecte</h2>
    <ul>
        <?php foreach ($recursos as $recurs): ?>
            <li><?= htmlspecialchars($recurs, ENT_QUOTES, 'UTF-8') ?></li>
        <?php endforeach; ?>
    </ul>
    <p>PHP ha generat esta pàgina al servidor.</p>
</body>
</html>
```

La llista està escrita en el codi per comprovar l’execució PHP, no ve de MariaDB. Pots simplificar-la a un títol i un paràgraf si encara no has treballat bucles. Els formularis, reserves i consultes reals s’introduiran després.

### Arrancar i comprovar

Amb Docker Desktop o el motor Docker arrancat, obri un terminal dins de `practica-r1m2`:

```sh
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=30
```

La primera arrencada descarrega les imatges i inicialitza la BBDD; pot tardar uns minuts. `config --quiet` comprova la configuració, però no demostra que els contenidors hagen arrancat.

| Comprovació | On o com | Resultat esperat |
|---|---|---|
| Landing | `http://localhost:8080` | Material Viu i els tres recursos. |
| PHP | Canviar `$producte` i recarregar | El títol canvia; el navegador rep HTML, no PHP. |
| phpMyAdmin | `http://localhost:8081` | Formulari d’inici de sessió. |
| BBDD | Usuari `alumne`, clau `alumne_demo_local` en phpMyAdmin | Es pot obrir `material_viu`, encara sense taules. |
| Estat | `docker compose ps` | Serveis en execució i `db` saludable. |

Si vols comprovar la BBDD des del terminal:

```sh
docker compose exec db mariadb -u alumne -p material_viu
```

Introduïx `alumne_demo_local` quan es demane. En la consola SQL, `SELECT DATABASE();` ha de retornar `material_viu`; `exit` ix de la consola. Esta comprovació d’infraestructura no exigix encara implementar persistència en PHP.

### Parar i tornar a arrancar

```sh
docker compose down
docker compose up -d
```

`down` elimina els contenidors i la xarxa del projecte, però conserva el volum de dades. No afegisques `-v` si vols conservar la BBDD. Les variables d’inicialització de MariaDB s’apliquen quan el volum està buit: canviar una clau al YAML no canvia automàticament els usuaris d’una BBDD ja creada.

Si els ports 8080 o 8081 estan ocupats, canvia només el port del teu ordinador: per exemple `127.0.0.1:8090:80`, i usa la nova URL. Dins dels contenidors, Apache continua escoltant en el port 80.

Referències de les imatges: [PHP amb Apache](https://hub.docker.com/_/php), [comprovació de salut de MariaDB](https://mariadb.com/docs/server/server-management/automated-mariadb-deployment-and-administration/docker-and-mariadb/using-healthcheck-sh) i [phpMyAdmin](https://hub.docker.com/_/phpmyadmin).

## 3. Errors habituals

| Què observes | Causa possible | Com comprovar-ho |
|---|---|---|
| La landing no respon | Port, ruta o volum incorrectes. | Contrasta URL del README, ports i logs. |
| PHP es mostra com a text | La ruta no passa per l’executor PHP. | Revisa el servei que atén la petició. |
| Només funciona en el teu ordinador | Hi ha passos o variables no documentats. | Reproduïx el README en una còpia separada. |

## 4. Modificació curta per practicar

Canvia un text de la landing i explica quin fitxer se servix i com arriba el canvi al navegador. Identifica en el Compose on es publica el port.

És pràctica de consolidació, sense lliurament avaluable addicional. Anota el canvi i el resultat; si uses IA, registra la consulta real i com l’has comprovat.

## 5. Comprova que ho entens

| Cas | Resultat esperat |
|---|---|
| Arrencada seguint el README | Landing accessible i serveis identificables. |
| URL incorrecta | Pots localitzar si el problema és de port, ruta o fitxer. |

Prediu el resultat abans de provar i explica quina peça el determina. Si no coincidix, localitza la causa amb el professorat en el temps de consolidació.

## 6. Connexió amb el pas següent

R2S0 prepara PHP i HTML abans dels formularis. No cal afegir login ni funcionalitat complexa per consolidar R1M2. L’ampliació de R1 és separada i docent; no es deduïx d’esta pràctica.

Consulta la [rúbrica de R1M2](../../03_com_s_avalua/rubriques/r1m2.md) per distingir els mínims del treball d’aula de les variants d’esta fitxa. L’exemple és de suport i no substituïx el teu projecte.
