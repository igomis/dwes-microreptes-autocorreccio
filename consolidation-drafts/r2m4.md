# R2M4. Consolidació: Estat, sessio i cookies

Esta fitxa es consulta després del treball d’aula. Servix per entendre errors i continuar aprenent; no és una nova entrega ni una recuperació individual del microrepte. La recuperació, si cal, correspon al repte complet.

## 1. Què cal entendre

Una variable de la petició no dura automàticament fins a la següent. La sessió guarda estat al servidor; una cookie pròpia pot guardar una preferència no sensible al client. Les rutes d’inclusió no són URL.

## 2. Exemple mínim explicat

En una reserva, la sessió pot conservar temporalment el recurs triat i una cookie la preferència de vista. La seqüència de comprovació és:

| Petició | Operació | Què observar |
|---|---|---|
| Triar recurs | Iniciar sessió i guardar l’identificador | Estat assignat al servidor. |
| Obrir resum | Iniciar sessió i llegir-lo | La tria continua disponible. |
| Canviar vista | Enviar cookie pròpia no sensible | Es rep en una petició posterior. |
| Reiniciar | Llevar l’estat temporal corresponent | La tria ja no apareix. |

En `config/bootstrap.php`, una base com `define('BASE_PATH', dirname(__DIR__));` permet importar una llibreria amb `require_once BASE_PATH . '/src/regles.php';`. Adapta les carpetes reals. Llig `$_SERVER['REQUEST_METHOD']` per distingir consulta i enviament; no el confongues amb una identitat autenticada. Tant sessió com cookies necessiten preparar capçaleres abans d’enviar HTML.

### Exemple en PHP

El formulari de tria pot enviar `recurs_id` a `triar.php`. Esta primera petició guarda la tria, crea la cookie i redirigix:

```php
<?php
session_start();

if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    http_response_code(405);
    exit('Mètode no permés');
}

$recursId = filter_input(INPUT_POST, 'recurs_id', FILTER_VALIDATE_INT);
if ($recursId === false || $recursId === null) {
    http_response_code(400);
    exit('Recurs incorrecte');
}

$_SESSION['recurs_id'] = $recursId;
setcookie('vista', 'compacta', [
    'expires' => time() + 30 * 24 * 60 * 60,
    'path' => '/',
    'httponly' => true,
    'samesite' => 'Lax',
]);

header('Location: resum.php');
exit;
```

En `resum.php`, una petició nova ja pot llegir la sessió i la cookie. El botó reinicia només la tria temporal; la preferència de vista es manté:

```php
<?php
session_start();

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    unset($_SESSION['recurs_id']);
    header('Location: resum.php');
    exit;
}

$recursId = $_SESSION['recurs_id'] ?? null;
$vista = $_COOKIE['vista'] ?? 'normal';
?>

<p>Recurs: <?= $recursId === null ? 'cap' : (int) $recursId ?></p>
<p>Vista: <?= htmlspecialchars($vista, ENT_QUOTES, 'UTF-8') ?></p>
<form method="post">
    <button type="submit">Reiniciar tria</button>
</form>
```

La cookie no està disponible en `$_COOKIE` en el mateix instant que executes `setcookie()`: el navegador la torna en la petició posterior a `resum.php`.

### Exemple equivalent amb Python (Flask)

En Flask, el mateix flux es pot concentrar en tres rutes:

```python
import os

from flask import Flask, abort, redirect, render_template, request, session, url_for

app = Flask(__name__)
app.config["SECRET_KEY"] = os.environ["SECRET_KEY"]


@app.post("/triar")
def triar():
    recurs_id = request.form.get("recurs_id", type=int)
    if recurs_id is None:
        abort(400, "Recurs incorrecte")

    session["recurs_id"] = recurs_id
    response = redirect(url_for("resum"))
    response.set_cookie(
        "vista",
        "compacta",
        max_age=30 * 24 * 60 * 60,
        httponly=True,
        samesite="Lax",
    )
    return response


@app.get("/resum")
def resum():
    return render_template(
        "resum.html",
        recurs_id=session.get("recurs_id"),
        vista=request.cookies.get("vista", "normal"),
    )


@app.post("/reiniciar")
def reiniciar():
    session.pop("recurs_id", None)
    return redirect(url_for("resum"))
```

El `templates/resum.html` mínim pot mostrar l'estat i oferir el reinici:

```html
<p>Recurs: {{ recurs_id if recurs_id is not none else "cap" }}</p>
<p>Vista: {{ vista }}</p>
<form method="post" action="{{ url_for('reiniciar') }}">
    <button type="submit">Reiniciar tria</button>
</form>
```

Abans d'arrancar-lo, definix un secret local, per exemple amb `SECRET_KEY='canvia-esta-clau' flask --app app run`. No versions el secret real. Per defecte, Flask guarda les dades de `session` en una cookie signada: el navegador pot conservar-les, però no modificar-les sense invalidar la firma. No hi guardes secrets. `request.method`, `request.headers` i `request.remote_addr` són dades tècniques de la petició, no una identitat autenticada.

## 3. Errors habituals

| Què observes | Causa possible | Com comprovar-ho |
|---|---|---|
| Capçaleres ja enviades | S’ha imprés HTML abans de preparar estat. | Busca eixida anterior al bootstrap. |
| Cookie no apareix immediatament | Es consulta la mateixa petició que l’ha creat. | Fes una nova petició. |
| Incloure falla des d’una altra ruta | S’usa una ruta relativa fràgil. | Resol des de la base comuna. |

## 4. Modificació curta per practicar

Tria un recurs, obri una segona pàgina i reinicia el flux. Explica què es lleva de sessió i si la preferència de vista ha de mantindre’s.

És pràctica de consolidació, sense lliurament avaluable addicional. Anota el canvi i el resultat; si uses IA, registra la consulta real i com l’has comprovat.

## 5. Comprova que ho entens

| Cas | Resultat esperat |
|---|---|
| Petició posterior a la tria | Llig l’estat esperat. |
| Després del reinici | No reutilitza la tria invalidada. |

Prediu el resultat abans de provar i explica quina peça el determina. Si no coincidix, localitza la causa amb el professorat en el temps de consolidació.

## 6. Connexió amb el pas següent
