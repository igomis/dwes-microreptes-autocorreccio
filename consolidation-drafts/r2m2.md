# R2M2. Consolidació: processament, reintent i confirmació

Esta fitxa es consulta després del treball d’aula. Servix per entendre un error concret i continuar; no és una nova entrega ni una recuperació individual.

## 1. Què cal entendre

Hi ha dos comportaments diferents:

- si l’entrada és incorrecta, el servidor mostra l’error i torna a pintar les dades aprofitables;
- si és correcta, la processa i mostra una confirmació o resum comprensible.

No cal introduir encara BBDD, sessió, autenticació, arrays d’errors ni una arquitectura completa.

## 2. Patró mínim

En una sol·licitud de visita, conserva el nom i el torn quan falta el motiu. Confirma només el cas correcte.

```php
$nom = trim($_POST['nom'] ?? '');
$motiu = trim($_POST['motiu'] ?? '');
$torn = $_POST['torn'] ?? '';
$error = $motiu === '' ? 'Explica el motiu.' : '';

$confirmacio = $error === ''
    ? ['nom' => $nom, 'motiu' => $motiu, 'torn' => $torn]
    : null;
```

En la plantilla, usa els valors rebuts en `value` i `selected`, sempre escapats. Si hi ha error, no mostres una confirmació d'èxit. Si no n’hi ha, mostra el resum a partir de les dades tractades.

## 3. Si treballes amb Python

Amb Flask, el patró és el mateix; canvien les eines:

```python
nom = request.form.get("nom", "").strip()
motiu = request.form.get("motiu", "").strip()
torn = request.form.get("torn", "")
error = "Explica el motiu." if not motiu else ""

confirmacio = None if error else {"nom": nom, "motiu": motiu, "torn": torn}
```

Passa `nom`, `torn` i `error` a `render_template`. Jinja escapa `{{ nom }}` per defecte. Marca l’opció amb una condició com `{% if torn == "mati" %}selected{% endif %}`. No uses `|safe` amb dades de l’usuari.

No cal conservar la dada entre peticions ni afegir SQLAlchemy o una BBDD en este microrepte. El guardat i la lectura posterior són una ampliació opcional.

## 4. Prova curta

| Cas | Resultat esperat |
|---|---|
| Nom `Aina`, motiu buit, torn `vesprada` | Error visible; nom i torn conservats; no es confirma com a correcte. |
| Corregir només el motiu | Cas acceptat amb confirmació o resum. |
| Torn manipulat | Error; el valor no es tracta com una opció vàlida. |

## 5. Errors habituals

| Què observes | Causa possible | Com comprovar-ho |
|---|---|---|
| El formulari torna buit | La plantilla no rep els valors enviats. | Provoca un error i inspecciona `value` i `selected`. |
| El torn sempre és el mateix | Està escrit com un literal fix. | Canvia’l i provoca de nou l’error. |
| Es confirma un cas invàlid | La confirmació ocorre abans de validar. | Comprova que amb error no apareix el resum d'èxit. |

## 6. Modificació curta

Provoca un error, conserva un text i una opció tancada, corregix només la dada errònia i comprova la confirmació final. Prediu el resultat abans de provar-lo.

És pràctica de consolidació, sense lliurament avaluable addicional. Si uses IA, registra la consulta real i com l’has comprovat.

## 7. Connexió amb R2M3

R2M3 usarà una dada real del flux per aplicar una regla. No convertisques esta consolidació en una pràctica de persistència formal.

Si el mínim ja està tancat, pots ampliar-lo guardant casos correctes en `JSON` i llegint-los després, o afegint una pujada de fitxer validada en servidor. En el segon cas, limita mida i tipus, genera un nom segur i prova un fitxer acceptat i un de rebutjat. Cap ampliació substituïx el reintent.
