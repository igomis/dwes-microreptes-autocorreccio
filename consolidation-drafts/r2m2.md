# R2M2. Consolidació: Processament, reintent i guardat funcional

Esta fitxa es consulta després del treball d’aula. Servix per entendre errors i continuar aprenent; no és una nova entrega ni una recuperació individual del microrepte. La recuperació, si cal, correspon al repte complet.

## 1. Què cal entendre

Conservar valors després d’un error i guardar una entrada correcta són dos problemes diferents. Cal tornar a pintar text, opció i checkbox quan corresponga, i poder recuperar després la dada acceptada.

## 2. Exemple complet explicat: sol·licitar una visita

Amplia el formulari de R2M1: la persona escriu el nom i el motiu, tria un torn i indica si vol avisos. Si falta el motiu, el servidor mostra l’error i conserva la resta. Quan tot és correcte, guarda la sol·licitud en un fitxer i obri una altra pàgina que la llig.

Usarem **un únic fitxer amb l’última sol·licitud**: una nova alta correcta substituïx l’anterior. És un guardat funcional mínim, no un historial ni una base de dades. No usem sessions, cookies ni autenticació.

### A. Estructura i arrencada

```text
practica-r2m2/
├── magatzem.php
├── dades/
└── public/
    ├── index.php
    └── ultima.php
```

Crea les carpetes i els tres fitxers següents. Des de `practica-r2m2`, executa:

```sh
php -S localhost:8000 -t public
```

Obri `http://localhost:8000`. La carpeta `dades/` ha de permetre escriptura a l’usuari que executa PHP. Queda fora de l’arrel pública: el navegador no ha de poder descarregar directament el fitxer de dades. Treballa amb dades fictícies.

Si uses Docker, adapta els muntatges perquè `public/` siga l’arrel web i PHP puga llegir `magatzem.php` en la carpeta superior i escriure en `dades/`. El Compose de R1M2 només munta `public/` en lectura i no incorpora estes carpetes addicionals; no n’hi ha prou amb copiar-li el formulari.

### B. `magatzem.php`: suport per guardar i llegir

Este fitxer resol el mecanisme de guardat. Pots estudiar primer el formulari i tornar després a estes funcions; saber implementar bloquejos de fitxer no és un requisit nou de R2M2.

```php
<?php
function guardarSollicitud(array $sollicitud): void {
    $json = json_encode($sollicitud, JSON_UNESCAPED_UNICODE | JSON_THROW_ON_ERROR);
    $fitxer = fopen(__DIR__ . '/dades/ultima.json', 'c+');
    if ($fitxer === false) {
        throw new RuntimeException('No es pot obrir el magatzem.');
    }
    try {
        if (!flock($fitxer, LOCK_EX)) {
            throw new RuntimeException('No es pot bloquejar el magatzem.');
        }
        if (!ftruncate($fitxer, 0) || !rewind($fitxer)
            || fwrite($fitxer, $json) !== strlen($json) || !fflush($fitxer)) {
            throw new RuntimeException('No es pot completar el guardat.');
        }
    } finally {
        fclose($fitxer);
    }
}

function llegirSollicitud(): ?array {
    $ruta = __DIR__ . '/dades/ultima.json';
    if (!is_file($ruta)) {
        return null;
    }
    $fitxer = fopen($ruta, 'r');
    if ($fitxer === false) {
        throw new RuntimeException('No es pot obrir el magatzem.');
    }
    try {
        if (!flock($fitxer, LOCK_SH)) {
            throw new RuntimeException('No es pot llegir el magatzem.');
        }
        $json = stream_get_contents($fitxer);
        if ($json === false) {
            throw new RuntimeException('Lectura incompleta.');
        }
        $dades = json_decode($json, true, 512, JSON_THROW_ON_ERROR);
        if (!is_array($dades)) {
            throw new RuntimeException('Format de dades incorrecte.');
        }
        return $dades;
    } finally {
        fclose($fitxer);
    }
}
```

El JSON conserva text i el booleà dels avisos. El bloqueig evita llegir mentre una altra petició està escrivint; tancar el fitxer allibera el bloqueig. És suport didàctic local: no substituïx una BBDD ni oferix garanties de recuperació davant d’una fallada de disc.

### C. `public/index.php`: recuperar, validar i tornar a pintar

```php
<?php
require_once __DIR__ . '/../magatzem.php';

$nom = '';
$motiu = '';
$torn = 'mati';
$avisos = false;
$error = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $nomRebut = $_POST['nom'] ?? '';
    $motiuRebut = $_POST['motiu'] ?? '';
    $tornRebut = $_POST['torn'] ?? '';
    $nom = is_string($nomRebut) ? trim($nomRebut) : '';
    $motiu = is_string($motiuRebut) ? trim($motiuRebut) : '';
    $torn = is_string($tornRebut) ? $tornRebut : '';
    $avisos = ($_POST['avisos'] ?? '') === 'si';

    // Una sola variable d’error: mostrem el primer problema trobat.
    if ($nom === '') {
        $error = 'Escriu el teu nom.';
    } elseif ($motiu === '') {
        $error = 'Explica el motiu de la visita.';
    } elseif (!in_array($torn, ['mati', 'vesprada'], true)) {
        $error = 'Tria un torn vàlid.';
    } else {
        // Només arribem al guardat quan la validació és correcta.
        try {
            guardarSollicitud([
                'nom' => $nom,
                'motiu' => $motiu,
                'torn' => $torn,
                'avisos' => $avisos,
            ]);
            header('Location: ultima.php', true, 303);
            exit;
        } catch (Throwable $problema) {
            error_log($problema->getMessage());
            $error = 'No s’ha pogut guardar. Revisa el magatzem i torna a provar.';
        }
    }
}
?>
<!doctype html>
<html lang="ca">
<head><meta charset="utf-8"><title>Sol·licitar visita</title></head>
<body>
<h1>Sol·licitar una visita</h1>
<?php if ($error !== ''): ?>
    <p role="alert"><?= htmlspecialchars($error, ENT_QUOTES, 'UTF-8') ?></p>
<?php endif; ?>
<form method="post">
    <p><label>Nom
        <input name="nom" value="<?= htmlspecialchars($nom, ENT_QUOTES, 'UTF-8') ?>">
    </label></p>
    <p><label>Motiu
        <textarea name="motiu"><?= htmlspecialchars($motiu, ENT_QUOTES, 'UTF-8') ?></textarea>
    </label></p>
    <p><label>Torn
        <select name="torn">
            <option value="" <?= !in_array($torn, ['mati', 'vesprada'], true) ? 'selected' : '' ?>>Tria un torn</option>
            <option value="mati" <?= $torn === 'mati' ? 'selected' : '' ?>>Matí</option>
            <option value="vesprada" <?= $torn === 'vesprada' ? 'selected' : '' ?>>Vesprada</option>
        </select>
    </label></p>
    <p><label>
        <input type="checkbox" name="avisos" value="si" <?= $avisos ? 'checked' : '' ?>>
        Vull avisos
    </label></p>
    <button type="submit">Guardar sol·licitud</button>
</form>
<p><a href="ultima.php">Consultar l’última sol·licitud guardada</a></p>
</body>
</html>
```

La validació es fa en servidor. Hem deixat els camps sense `required` per poder observar l’error del backend directament. En el teu producte, pots complementar-lo amb validació del navegador.

Si falla una condició, **no hi ha redirecció ni guardat**: PHP continua fins a l’HTML amb les variables rebudes. `value` conserva el nom; el contingut de `textarea`, el motiu; `selected`, el torn; i `checked`, la preferència. No es conserva com a opció vàlida un torn manipulat que no està permés.

Si el guardat funciona, la resposta `303` demana al navegador obrir `ultima.php` amb una petició GET. Recarregar eixa pàgina torna a llegir les dades, sense reenviar el formulari. La redirecció és una ajuda del model, no un criteri nou d’avaluació. Si el guardat falla, es mostra un error i les dades continuen en el formulari.

### D. `public/ultima.php`: lectura en una petició posterior

```php
<?php
require_once __DIR__ . '/../magatzem.php';
$sollicitud = null;
$error = '';
try {
    $sollicitud = llegirSollicitud();
} catch (Throwable $problema) {
    error_log($problema->getMessage());
    $error = 'No s’ha pogut llegir la sol·licitud guardada.';
}
?>
<!doctype html>
<html lang="ca">
<head><meta charset="utf-8"><title>Última sol·licitud</title></head>
<body>
<h1>Última sol·licitud guardada</h1>
<?php if ($error !== ''): ?>
    <p role="alert"><?= htmlspecialchars($error, ENT_QUOTES, 'UTF-8') ?></p>
<?php elseif ($sollicitud === null): ?>
    <p>Encara no hi ha cap sol·licitud guardada.</p>
<?php else: ?>
    <dl>
        <dt>Nom</dt>
        <dd><?= htmlspecialchars($sollicitud['nom'], ENT_QUOTES, 'UTF-8') ?></dd>
        <dt>Motiu</dt>
        <dd><?= htmlspecialchars($sollicitud['motiu'], ENT_QUOTES, 'UTF-8') ?></dd>
        <dt>Torn</dt>
        <dd><?= htmlspecialchars($sollicitud['torn'], ENT_QUOTES, 'UTF-8') ?></dd>
        <dt>Avisos</dt>
        <dd><?= $sollicitud['avisos'] ? 'Sí' : 'No' ?></dd>
    </dl>
<?php endif; ?>
<p><a href="index.php">Tornar al formulari</a></p>
</body>
</html>
```

Esta pàgina no llig `$_POST`: obté la informació del fitxer. Per això pots obrir-la directament en una altra pestanya o parar i tornar a arrancar el servidor i continuar veient la dada guardada. L’exemple compartix l’última sol·licitud entre totes les visites al servidor local; no hi ha dades privades per usuari ni autenticació.

### E. Prova guiada completa

1. Obri `ultima.php` abans de guardar: indica que encara no hi ha dades.
2. En el formulari escriu `Aina`, deixa el motiu buit, tria `Vesprada` i marca avisos.
3. Envia: apareix l’error de motiu; nom, torn i avisos es mantenen. No s’ha creat cap sol·licitud.
4. Escriu només el motiu, per exemple `Conéixer el taller`, i torna a enviar.
5. El navegador obri `ultima.php` i mostra les quatre dades guardades.
6. Recarrega o obri eixa URL en una altra pestanya: la dada continua disponible.
7. Envia després un formulari invàlid: l’última sol·licitud correcta no ha de canviar.
8. Guarda una nova sol·licitud correcta amb avisos desmarcats: substituïx l’anterior i mostra `No`.

No puges `dades/ultima.json` al repositori com si fora codi: és una dada d’execució. Pots ignorar-la en `.gitignore` i documentar que cal crear la carpeta `dades/`.

## 3. Errors habituals

| Què observes | Causa possible | Com comprovar-ho |
|---|---|---|
| Nom perdut en l’error | Es pinta un input buit. | Inspecciona el `value` retornat. |
| Torn sempre igual | L’opció es marca de forma fixa. | Canvia el torn i provoca un error. |
| «Guardat» però no reapareix | Només es mostra la petició. | Fes una lectura posterior del magatzem triat. |

## 4. Modificació curta per practicar

Provoca un error deixant un camp buit però conservant els altres. Corregeix només eixe camp i comprova la lectura posterior de la reserva acceptada.

És pràctica de consolidació, sense lliurament avaluable addicional. Anota el canvi i el resultat; si uses IA, registra la consulta real i com l’has comprovat.

## 5. Comprova que ho entens

| Cas | Resultat esperat |
|---|---|
| Motiu buit, Aina, vesprada i avisos | Error visible; nom, torn i checkbox conservats; magatzem intacte. |
| Motiu corregit | Redirecció i lectura posterior de les quatre dades. |
| Nova petició GET a `ultima.php` | La dada ve del fitxer, sense dependre de POST. |
| Nova sol·licitud correcta sense avisos | Substituïx l’anterior i mostra `No`. |

Prediu el resultat abans de provar i explica quina peça el determina. Si no coincidix, localitza la causa amb el professorat en el temps de consolidació.
