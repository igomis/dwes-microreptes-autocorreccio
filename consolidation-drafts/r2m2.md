# R2M2. Consolidació: processament, reintent i guardat funcional

Esta fitxa es consulta després del treball d’aula. Servix per entendre un error concret i continuar; no és una nova entrega ni una recuperació individual.

## 1. Què cal entendre

Hi ha dos comportaments diferents:

- si l’entrada és incorrecta, el servidor mostra l’error i torna a pintar les dades aprofitables;
- si és correcta, la processa, la guarda amb un mecanisme simple i permet recuperar-la després.

No cal introduir encara BBDD, sessió, autenticació, arrays d’errors ni una arquitectura completa.

## 2. Patró mínim

En una sol·licitud de visita, conserva el nom i el torn quan falta el motiu. Guarda només el cas correcte.

```php
$nom = trim($_POST['nom'] ?? '');
$motiu = trim($_POST['motiu'] ?? '');
$torn = $_POST['torn'] ?? '';
$error = $motiu === '' ? 'Explica el motiu.' : '';

if ($error === '') {
    guardarSollicitud(['nom' => $nom, 'motiu' => $motiu, 'torn' => $torn]);
}
```

En la plantilla, usa els valors rebuts en `value` i `selected`, sempre escapats. Si hi ha error, no guardes. Si no n’hi ha, mostra després la dada des del mecanisme de guardat, no directament des de `POST`.

## 3. Si treballes amb Python

Amb Flask, el patró és el mateix; canvien les eines:

```python
nom = request.form.get("nom", "").strip()
motiu = request.form.get("motiu", "").strip()
torn = request.form.get("torn", "")
error = "Explica el motiu." if not motiu else ""

if not error:
    guardar_sollicitud({"nom": nom, "motiu": motiu, "torn": torn})
```

Passa `nom`, `torn` i `error` a `render_template`. Jinja escapa `{{ nom }}` per defecte. Marca l’opció amb una condició com `{% if torn == "mati" %}selected{% endif %}`. No uses `|safe` amb dades de l’usuari.

El guardat pot ser provisional i senzill, però una petició posterior ha de poder recuperar la dada correcta. No cal afegir SQLAlchemy ni una BBDD en este microrepte.

## 4. Prova curta

| Cas | Resultat esperat |
|---|---|
| Nom `Aina`, motiu buit, torn `vesprada` | Error visible; nom i torn conservats; no es guarda. |
| Corregir només el motiu | Cas acceptat i guardat. |
| Obrir el resum després | La dada ve del mecanisme de guardat. |
| Torn manipulat | Error; el valor no es tracta com una opció vàlida. |

## 5. Errors habituals

| Què observes | Causa possible | Com comprovar-ho |
|---|---|---|
| El formulari torna buit | La plantilla no rep els valors enviats. | Provoca un error i inspecciona `value` i `selected`. |
| El torn sempre és el mateix | Està escrit com un literal fix. | Canvia’l i provoca de nou l’error. |
| Es guarda un cas invàlid | El guardat ocorre abans de validar. | Comprova que amb error el magatzem no canvia. |
| «Guardat» però no reapareix | Només es mostra la mateixa petició. | Fes una lectura posterior. |

## 6. Modificació curta

Provoca un error, conserva un text i una opció tancada, corregix només la dada errònia i comprova la lectura posterior. Prediu el resultat abans de provar-lo.

És pràctica de consolidació, sense lliurament avaluable addicional. Si uses IA, registra la consulta real i com l’has comprovat.

## 7. Connexió amb R2M3

R2M3 usarà una dada real del flux per aplicar una regla. No convertisques esta consolidació en una pràctica de persistència formal.
