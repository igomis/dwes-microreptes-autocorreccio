# R4M2. Consolidació: Implementació del primer endpoint funcional

Esta fitxa es consulta després del treball d’aula. Servix per entendre errors i continuar aprenent; no és una nova entrega ni una recuperació individual del microrepte. La recuperació, si cal, correspon al repte complet.

## 1. Què cal entendre

L’endpoint ha de convertir una petició en una resposta estructurada amb dades o una acció real. Reutilitza la persistència de R3 i contrasta el comportament amb el contracte.

## 2. Exemple mínim explicat

Implementa en el teu framework el recorregut de consulta de visites: ruta amb identificador → controlador → lectura de la visita → resposta JSON. Si la dada no existix, aplica l’error del contracte.

Amb el servidor local arrancat i una visita demo existent, una petició de prova és:

```sh
curl -i http://localhost:8000/api/visites/12
```

Adapta port, ruta i identificador al teu projecte. `-i` mostra capçaleres i estat junt amb el cos. Si el contracte de R4M1 era el de la fitxa anterior, espera `200`, JSON i les dades reals de la visita. Canvia una dada de prova a través del mecanisme del projecte i repetix la consulta: ha de reflectir-la, sense editar el codi de resposta. Això ajuda a detectar un JSON fix que només simula la lectura.

## 3. Errors habituals

| Què observes | Causa possible | Com comprovar-ho |
|---|---|---|
| Sempre retorna la mateixa visita | Resposta fixa o identificador ignorat. | Consulta dues dades diferents. |
| Es barreja HTML amb JSON | Hi ha depuració o plantilla indeguda. | Inspecciona el cos complet. |
| Contracte i camps no coincidixen | La implementació ha derivat. | Compara nom, tipus i estructura. |

## 4. Modificació curta per practicar

Consulta una visita existent i una inexistent. Localitza on la lectura determina la resposta i explica per què el controlador no inventa una dada quan no la troba.

És pràctica de consolidació, sense lliurament avaluable addicional. Anota el canvi i el resultat; si uses IA, registra la consulta real i com l’has comprovat.

## 5. Comprova que ho entens

| Cas | Resultat esperat |
|---|---|
| Identificador existent | Resposta estructurada amb dades reals. |
| Identificador inexistent | Error coherent amb el contracte triat. |

Prediu el resultat abans de provar i explica quina peça el determina. Si no coincidix, localitza la causa amb el professorat en el temps de consolidació.

## 6. Connexió amb el pas següent

R4M3 afegirà o consolidarà el control d’accés del servei. No cal reobrir tota l’arquitectura de BBDD de R3.

Consulta la [rúbrica de R4M2](../../03_com_s_avalua/rubriques/r4m2.md) per distingir els mínims del treball d’aula de les variants d’esta fitxa. L’exemple és de suport i no substituïx el teu projecte.
