# R3M4. Consolidació: Components de vista i manteniment d'un recurs

Esta fitxa es consulta després del treball d’aula. Servix per entendre errors i continuar aprenent; no és una nova entrega ni una recuperació individual del microrepte. La recuperació, si cal, correspon al repte complet.

## 1. Què cal entendre

R3M4 fa evolucionar el flux de creació cap al manteniment d'un recurs existent. Un component de vista evita duplicació; `PUT/PATCH` actualitza; `DELETE` elimina; la validació, CSRF i les regles del domini mantenen la BBDD coherent.

## 2. Exemple mínim explicat

Si el primer flux crea una visita, R3M4 pot permetre editar-ne el títol i eliminar només les visites que encara no tenen sol·licituds. Una targeta de visita rep la visita i els enllaços d'acció com a entrada, i es reutilitza en el llistat general i en el detall.

El formulari d'edició envia `PATCH` o l'equivalent server-rendered del framework; la ruta valida i torna a llegir la visita de la BBDD. L'eliminació envia `DELETE` o equivalent amb CSRF. Una visita sense sol·licituds s'elimina; una visita amb sol·licituds mostra l'error i no canvia la BBDD.

Si el framework usa formularis `POST` per convenció, documenta com eixa ruta representa l'actualització o l'eliminació. No uses `GET` per canviar dades.

## 3. Errors habituals

| Què observes | Causa possible | Com comprovar-ho |
|---|---|---|
| El mateix HTML apareix copiat | No s'ha creat un component reutilitzable. | Localitza els dos renderitzats i la peça compartida. |
| L'edició diu que ha funcionat però la BBDD no canvia | La resposta usa la petició sense persistir o rellegir. | Recarrega el recurs des de la BBDD. |
| Cancel·lar usa `DELETE` | S'ha confós transició d'estat amb eliminació. | Comprova si el recurs ha de continuar existint. |
| Identificador inexistent causa excepció visible | Falta usar la resolució o resposta `404` del framework. | Prova un identificador inexistent. |
| R3M3 deixa de funcionar | S'ha canviat codi compartit sense regressió. | Repetix el cas positiu anterior. |

## 4. Modificació curta per practicar

Extrau una etiqueta d'estat o grup de botons a un component, usa'l en el llistat i en el detall, i modifica una regla perquè una visita amb sol·licituds no es puga eliminar.

És pràctica de consolidació, sense lliurament avaluable addicional. Anota el canvi i el resultat; si uses IA, registra la consulta real i com l’has comprovat.

## 5. Comprova que ho entens

| Cas | Resultat esperat |
|---|---|
| Edició correcta | Canvia la BBDD i el valor nou apareix després de redirigir. |
| Edició invàlida | Mostra errors i conserva la BBDD anterior. |
| Eliminació permesa | El recurs desapareix i la resposta ho confirma amb dades reals. |
| Eliminació denegada | Mostra error i no deixa canvis parcials. |
| Identificador inexistent | Retorna `404` o resposta controlada equivalent. |
| Primer flux després del canvi | Continua registrant i mostrant correctament. |

Prediu el resultat abans de provar i explica quina peça el determina. Si no coincidix, localitza la causa amb el professorat en el temps de consolidació.

## 6. Connexió amb el pas següent

R3M5 protegirà l'actualització o l'eliminació amb autenticació i autorització. No cal anticipar rols complexos, API ni integració externa.

Consulta la [rúbrica de R3M4](../../03_com_s_avalua/rubriques/r3m4.md) per distingir els mínims del treball d’aula de les variants d’esta fitxa. L’exemple és de suport i no substituïx el teu projecte.
